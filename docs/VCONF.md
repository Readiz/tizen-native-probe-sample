# vconf 검증 범위와 준비 조건

[프로젝트 안내](../README.ko.md) | [API 범위](API_MATRIX.md)

검증 목표는 **Web App에 포함한 Native Service가 실제 필요한 vconf key에 접근할 수 있는지** 확인하는 것이다. 현재 버전에는 vconf 호출을 구현하지 않았다. 사용할 제품 key 이름과 값의 타입, 필요한 동작도 아직 지정되지 않았으므로 예시 key를 임의로 골라 읽거나 쓰지 않는다.

플랫폼에 vconf 관련 서비스가 있다는 것, SDK에서 헤더가 보인다는 것, 특정 key를 앱이 사용할 수 있다는 것은 각각 다른 근거다. Tizen 플랫폼 문서에는 부팅 과정의 `vconf-setup`이 등장하지만 이것만으로 삼성 TV 앱의 vconf API 지원이나 접근 권한을 판단할 수는 없다. [Tizen 플랫폼 포팅 문서](https://github.com/Samsung/tizen-docs/blob/master/docs/platform/porting/kernel.md)

## 구현 전에 필요한 정보

| 입력 | 확인할 내용 | 현재 상태 |
| --- | --- | --- |
| 제품 SDK | TV 모델과 펌웨어에 맞는 SDK 및 rootstrap, 헤더와 링크 라이브러리 | 미확인 |
| 대상 key | 정확한 이름과 용도, 제품 SDK에서 정의한 값의 타입 | 미지정 |
| 필요한 동작 | 읽기, 쓰기, 변경 알림 중 필요한 항목 | 미지정 |
| 실행 환경 | hybrid 패키지의 실제 Native Service, 서명과 앱 식별자, 접근 정책 | 실기 미검증 |
| 쓰기 조건 | 변경 허용 여부, 기존 값 보존과 복원 방법, 시험 종료 기준 | 미지정 |

실제 key 목록은 제품 환경에 따라 비공개일 수 있다. 이 공개 저장소에는 임의 key, 조직 내부 경로, 실제 설정값을 포함하지 않는다. SDK가 제공하는 함수 선언과 반환 규약을 확인한 뒤 해당 key와 타입에 맞춰 호출을 구현한다. 현재 문서는 확인하지 않은 함수 서명이나 라이브러리 이름을 확정값으로 제시하지 않는다.

## 확인 순서

1. **컴파일과 링크:** 제품 rootstrap의 헤더와 라이브러리로 최소 호출 코드를 빌드한다. 호스트 PC 라이브러리나 Mobile/Wearable rootstrap으로 대체하지 않는다. 헤더를 찾은 결과와 링크가 성공한 결과를 따로 남긴다.
2. **앱 실행 환경:** 샘플의 실제 hybrid 패키지 안에서 Native Service를 실행하고 IPC 연결부터 확인한다. 다른 시스템 프로세스나 개발용 셸의 성공은 앱의 성공으로 기록하지 않는다.
3. **읽기:** 명시된 key와 타입으로 호출하고 반환 코드와 값을 구분한다. 호출 실패를 `0`, `false`, 빈 문자열로 치환하지 않는다. 읽기를 생략했다면 미검증으로 둔다.
4. **쓰기:** 쓰기가 필요한 key에 한해 명시적으로 실행한다. 기존 값, 요청 값, 원본 반환 코드와 후속 조회 결과를 구분하고 정한 복원 절차를 수행한다. 읽기 성공만으로 쓰기 권한을 추정하지 않는다.
5. **변경 알림:** 등록 결과, 실제 변경 뒤 callback 수신, 해제 결과를 각각 기록한다. 등록 성공만으로 알림 수신을 검증한 것으로 표시하지 않는다.
6. **재현 정보:** 모델, 펌웨어, SDK/rootstrap, 서명 수준과 Native 실행 환경을 결과에 연결한다. 모델 하나의 성공을 다른 연도나 전체 TV 제품군으로 일반화하지 않는다.

진단 JSON으로 결과를 확장할 때는 구현 여부, 실행 여부, 동작별 결과를 별도로 기록한다. 미구현, 빌드 제외, 미실행, 실제 오류와 실제 성공을 구분하고, 오류에는 SDK가 반환한 원본 코드를 보존한다. KeyManager와 다른 플랫폼 API도 같은 기준을 적용한다.

## 현재 제공 범위

- 제공: 검증 목표, 필요한 입력, SDK부터 실제 앱 권한까지의 검사 절차.
- 미제공: vconf 호출 코드, 제품 key 목록, SDK 빌드 결과, TV에서의 읽기와 쓰기 및 변경 알림 결과.

이 문서가 추가됐다는 사실은 vconf 지원을 확인했다는 의미가 아니다. 구체적인 제품 key와 SDK 계약이 확보되면 Native API 검사에 추가할 수 있다.
